# Промежуточный эксперимент: восстановление после общего скачка

Эти отчёты относятся к V3 без остаточного ускорения при обрыве и без последующих исправлений коротких/задержанных интервалов. Они не являются метриками финального решения. Исходная точка — сохранённая версия первого раунда, а не Git HEAD сокомандника.

Первый вариант сохранял признак скачка, вычисленный относительно последнего принятого колеса. Он мог накопить ошибочную невязку на допустимом резком торможении и плохо принимал обратный скачок к правильным показаниям. Второй вариант уточнил условие по соседним исходным отсчётам. V3 дополнительно выделил tentative: показания, принятые только из-за расширившейся неопределённости модели, не становятся независимым подтверждением и не обучают адаптацию.

На 72 синтетических сценариях 30618 среднеквадратичная агрегация RMSE снизилась 0,8423→0,7657 м/с. Это равновесная диагностическая сводка искусственных сценариев, не robustness-score организаторов. При общем скачке +4 м/с на 10 с ошибка конца пути на равномерном движении снизилась примерно 40→23,25 м; длинные сбои всё ещё могут быть приняты. Чистые данные, одиночные скачки, пропуски и задержки в этом эксперименте не изменились.

Номинальный GNSS-прокси 30618: train 0,060600→0,060629 м/с; validation 0,03314565→0,03314704. Незначительные ухудшения сохранены в CSV, а не исключены. Физический режим train 30639 не изменился. На отдельных возвратах после общей заморозки/плавного смещения дополнительная защита может замедлить восстановление. Без независимого наблюдения общая плавная ошибка не всегда различима.

`recovery_v3.patch` применяется только к сохранённому baseline первого раунда. Хэши исходников и отчётов приведены в `manifest.json`; бинарные хэши и точные входные хэши — внутри fault JSON. Для повторения собрать baseline и вариант, затем вызвать:

```bash
python3 evaluation/wheel_fault_benchmark.py --before /path/to/baseline/replay_cli \
  --after /path/to/v3/replay_cli \
  --table ros2_ws/src/tram_odometry/assets/drive_accel_table.csv \
  --out /tmp/recovery-v3.json
```

Для 30639 убрать таблицу и передать `--vehicle 30639 --seeds 11 37`. Номинальные CSV получены `evaluation/core_benchmark.py` на train/validation с тем же V3 исполняемым файлом; это исторический GNSS-прокси. Последующие тесты обнаружили пропуск резких скачков при интервале менее 45 мс и пакетной доставке; финальная реализация проверяет разрыв отдельно по времени заголовка.
