# Раунд 3: восстановление датчиков, RTK и проверка карты

Сравнение: зафиксированный `50bd771` → runtime `1b4a395`. Хэши исходников,
переносимых executable и ROS-ноды — в
[final_freeze.json](../evaluation/results/round3/final_freeze.json).
Это повышение надёжности с известными компромиссами, а не улучшение каждой метрики.
Ранее изученные train/validation/holdout и открытый эталон не являются новым скрытым тестом.

## Что изменено

- После совместного зависания один вернувшийся датчик может пройти обычный
  фильтр инновации, даже если второй отсутствует или продолжает публиковать
  неизменные значения. Второй остаётся исключённым до изменения показаний.
  Короткое ожидание сохраняет возможность восстановления пары в любом порядке callback.
- Для восстановления пары нужны свежие согласованные исходные временные метки.
  Изменение payload при повторном header не считается новым измерением.
- Любая смена команды во время зависания запрещает приближённую компенсацию пути,
  включая возврат `+4→0→+4`. Компенсация остаётся ограниченной и применяется
  только к будущим выходам, без изменения уже опубликованных сообщений.
- Сглаживание признака ускорения зависит от времени, а не числа сообщений:
  проверки покрывают 10, 20, 25, 50 и 100 Гц.
- Смена команды сама по себе больше не объявляет два исправных датчика зависшими.
  Сохраняется эвристика «разгон/торможение перед точным плато».
- Стартовая привязка предпочитает `status=2`. RTK и остальные fix имеют отдельные
  окна и временные истории. RTK-курс требует RTK обоих антенн; иначе используется
  геометрия кузова на карте, а без карты — заданный курс. Срок ожидания остаётся
  5 с, задержка запасной антенны — 1,5 с. Без RTK доступны обычные fix по окончании
  окна; без GNSS — относительный кадр `odom`.
  Известный риск: без карты при правильной смешанной паре и ошибочном
  заданном курсе на 90° эта политика даёт 13,96 м ошибки положения уже
  на старте, а в движении ошибка может расти. В поставляемом режиме карта
  присутствует, но её направление кузова тоже может отличаться от фактического.
  [Разбор и принятое ограничение](../evaluation/results/round3/startup_independent_review.md).

Продольная оценка по-прежнему использует физическую/табличную модель тяги,
адаптивную поправку и скалярное обновление скорости с дисперсиями и защитами
датчиков. Это не новый полный EKF. GNSS-скорость и комплексированный эталон
не подаются в рабочий фильтр; разрешённые GNSS-fix корректируют только привязку положения.

[30639](../evaluation/results/round3/synthetic_30639.json).
Точное здоровое плато после разгона всё ещё может активировать эвристику:
по двум одинаковым скоростям и команде невозможно гарантированно отличить его
от общего зависания без дополнительного независимого измерения.

Новый GNSS-evaluator отдельно считает потерянные/добавленные абсолютные выходы

разрешённые входы; очищенная пара GNSS строится отдельно из исходных MF/RF и не изменяется
инъекциями пропусков/задержек. Это те же датчики: первые 30 с совпадают
с входными данными решения, поэтому прокси не является независимой

На открытом бэге офлайн полное Navigation ухудшилось:
**3D RMSE 1,474923 → 1,544901 м (+4,74%)**, на 26 884 общих сопоставлениях.
Скорость осталась **0,048048 м/с**, ошибка конца — **0,100749 м**.
В стартовом окне master имеет status0, rover получает RTK через 1,23 с;
старый алгоритм выбирал master и смешанную пару для курса, новый — RTK rover
и направление кузова по карте. Начальное смещение между решениями — 2,137 м,
разница курса — 9,36°. Основная потеря — первые 60 с; после 300 с различие
координат менее 0,000608 м. Потерянный один ранний выход находится до эталона
и не объясняет ухудшение RMSE. Это явный компромисс доверия качеству RTK,
а не подтверждённый выигрыш точности на данном открытом маршруте.
[Разбор причины](../evaluation/results/round3/public_startup_delta.json),
[абляции окончательной сборки](../evaluation/results/round3/reference_ablation.json).

## Официальная карта и новые ответы организаторов

Проверен вариант ограниченной коррекции только обратного пути по Pathgraph.
Он отклонён до просмотра открытого эталона: на 42 train bag общий XY RMSE
**6,029681 → 6,030769 м**, 4 улучшения / 17 ухудшений / 19 без изменений;
два bag без абсолютной привязки остаются учтены в coverage.
Наш обратный путь уже совпадает с внутренней частью официальной линии до
**0,0508 м поперечного RMS**. Официальные 4709 точек покрывают один путь,
а не оба направления и кольца. Сохраняем текущий XY и официальную высоту Z.
[Полный эксперимент и границы выводов](../evaluation/results/round3/official_xy_decision.md).

| Ответ организаторов | Выполнение |
|---|---|
| Эталон — `base_link`, прямое сравнение XYZ | Физические плечи антенн, единый фиксированный кадр; без подгонки к эталону |
| MGRS `37UCB`, приведён контрольный пример | Проверяется unit-тестом; x не обрезается по 100 км |
| В стартовом окне гарантирован RTK | Реализован приоритет status2, ограниченный fallback |
| `driver_position_cmd` будет присутствовать | Сообщение из основного датасета входит в пакет |
| Проверяют 30618; различия трамваев — плюс | Табличная калибровка 30618, отдельная конфигурация 30639 и проверки обоих |
| Маршрут регулярный; кольца можно и нужно восстанавливать | Существующие восстановленные кольца и обе ветви конечной сохранены |
| Разрешено восстановление тупиков депо | Разрешение не означает обязательный тест: депо не добавлено без проверенной геометрии |
| Скорость — выход внутренней комплексированной системы | Открытый fused-reference оценивается отдельно от GNSS-прокси |

Неоднозначный ответ о точности карты не трактуется как запрет обучающей геометрии.
Полный Z-датум GNSS отдельно не разъяснён; официальная высота применяется в
покрытой части линии, вне её сохраняется имеющаяся оценка.

## Финальный официальный ROS 1×

Полный прогон runtime `1b4a395` завершён штатно за 1316.45 с:
Ubuntu 22.04 / ROS 2 Humble, arm64, Docker **2 CPU / 512 MiB**.
Записаны все **65 579** эталонных сообщений. Процессы завершились с кодом 0.
Незавершённый предварительный прогон исключён из итоговых результатов.

| Официальный ATS | Предыдущий ROS-раунд `e248a96` | Раунд 3 |
|---|---:|---:|
| 3D RMSE, м | 1,540887 | **1,553866** |
| Максимальная 3D ошибка, м | 11,306111 | 11,309519 |
| RMSE скорости, м/с | 0,051973 | 0,051836 |
| Пар положения и скорости | 28 531 | 28 646 |

Прямое сравнение ATS показывает +0,84% ошибки положения. Небольшое улучшение
ATS скорости не считаем устойчивым выигрышем: на **27 153 общих метках**
записанных выходов 3D RMSE **1,525571 → 1,549435 м** (+1,56%), а скорость
**0,0489853 → 0,0490720 м/с** (+0,18%). Ошибка конца **0,115110 → 0,128599 м**.
Общая маска убирает различие набора выходных меток, но не различие порядка
DDS callback между двумя запусками. Поэтому эти ROS-числа не смешиваются
с детерминированным replay `50bd771→1b4a395` выше.
[Общая маска](../evaluation/results/round3/ros_round2_vs_round3_common.json).

размеченные реальные отказы и точная геометрия/курс на кольцах. Добавление
сложного фильтра само по себе не устраняет неразличимость общего зависания.
