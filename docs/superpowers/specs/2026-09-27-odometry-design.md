# Проверяемая резервная одометрия

Пользователь одобрил выполнение рекомендаций аудита 27 сентября и непрерывную работу до проверенного результата. Архитектура сохраняет гибридную физическую модель, причинные измерения и ROS-контракт. Альтернатива полной замены фильтра несёт лишний риск перед сдачей; простая настройка коэффициентов не исправляет разрыв валидации. Выбран общий переносимый C++ pipeline, используемый ROS и CLI.

## Контракт

Вход: приёмные и исходные метки контроллера, двух тележек, разрешённых GNSS fix/vel. Эталон `/localization/kinematic_state` читается только оценщиком. Выход: скорость и позиция base_link в непрерывном MGRS, диагностика качества и коррекций. Все исправления причинны. Без GNSS сохраняется резервная одометрия; сомнительные GNSS не должны резко менять состояние.

## Части решения

1. Валидация: decoder Odometry, evaluator с метриками скорости/XYZ/3D, охватом, manifest эксперимента; одинаковая маска baseline/candidate. ROS-скрипт запуска с официальным checker, без demo relay.
2. Pipeline: существующий estimator плюс вынесенный из ноды трекер маршрута/старта. Один код для node и полного replay. Выходы на принятых входных событиях, штампы не из будущего.
3. Коррекция: проверенные одиночные/парные GNSS-fix корректируют продольную привязку; GNSS velocity опционален, проверяется отдельно. Возврат после outage не требует двух одновременных антенн. Тесты выбросов, задержек, повторов, восстановления.
4. Карта: оценить официальный JSON относительно своей карты по геометрии, сохранять обе стороны и петли. Никакого построения карты по эталону проверочного bag. Высоту использовать без повторного смещения антенны.
5. Скорость: разделить точность исправных измерений и режим отказа. Каждое изменение подтверждать train/validation и стресс-тестами, официальный bag не использовать для подбора параметров.
6. Сдача: стандартные тесты, сборка ROS, реальные прогоны, ресурсные ограничения, актуальные документы и архив только с исходниками/производными asset.

## Условия завершения

Тесты и сборка проходят; реальные ROS-выходы оцениваются checker; воспроизводимые before/after числа и варианты GNSS сохранены; небезопасные улучшения не включены по умолчанию; ограничения и происхождение данных явно описаны. Статистическое превосходство на неизвестном тесте не заявляется.
