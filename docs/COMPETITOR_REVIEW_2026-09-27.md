## Проверенные различия, влияющие на сравнение

### KroLor

Финальный пакет `tram_odometry` оборачивает модель и включает поздние GNSS-поправки. В отчёте указаны 426 коррекций и одно переключение ветки. Наша конфигурация тоже поддерживает поздний GNSS. Ограничение GNSS только стартом относится к отдельным испытаниям.

Переход 1,772→1,209 м в их отчёте сравнивает разные ноды и число выходов: 38 318 против 26 210. Более полезна их отдельная проверка одной обёртки: около 1,80 м без позднего GNSS и 1,22 м с ним. Это самостоятельные измерения авторов. [Отчёт KroLor](https://github.com/KroLor/tram-backup-odometry/blob/c1b6c77ca08bd9f687b8cc4b58e5c3b0b51bd673/docs/REPORT.md#L8).

Их преимущества для изучения: более полный граф петель/подъездов, вероятностное определение ветки по профилю скорости, поправка масштаба по остановкам, переключение на резервный оцениватель с сохранением пути. У нас подробнее защищены поздние GNSS: геометрия пары антенн, зависание координат, подтверждение несколькими эпохами и ограничение поправки. [GNSS и ветки](https://github.com/KroLor/tram-backup-odometry/blob/c1b6c77ca08bd9f687b8cc4b58e5c3b0b51bd673/src/tram_odometry/tram_odometry/estimators/backup_model.py#L127). [Резервирование](https://github.com/KroLor/tram-backup-odometry/blob/c1b6c77ca08bd9f687b8cc4b58e5c3b0b51bd673/src/tram_odometry/tram_odometry/supervisor.py#L86).

### Alexaid1

Сдвиг выдаваемого состояния на 80 мс реализован явно: скорость и путь интерполируются для `t−0.08`, сообщение помечается временем `t`. Авторы объясняют это компенсацией наблюдаемого запаздывания эталона. Их офлайн-ошибка скорости меняется с 0,046 до 0,026 м/с после такого сдвига. Для сравнения оценивателей нужен единый временной контракт. [Реализация сдвига](https://github.com/Alexaid1/tram-backup-odometry/blob/b2cfa3d94844cf3b8e1e129a026702bb7b9beeb2/ros2_ws/src/tram_odometry/src/core/estimator.cpp#L595).

Проверка каталога остановок по двум частям данных даёт медиану RMSE положения 7,67123→3,37575 м. В сохранённом `tools/_cv.json` 68 строк, хотя текст отчёта говорит о 69 записях. При разделении заменяется каталог остановок, карта и конфигурация модели остаются общими. Поэтому это проверка переноса каталога, а не всей процедуры обучения. [Проверка каталога остановок](https://github.com/Alexaid1/tram-backup-odometry/blob/b2cfa3d94844cf3b8e1e129a026702bb7b9beeb2/tools/cross_validate.py#L22).

В репозитории есть явная настройка по открытой записи: временной сдвиг, шумы фильтра, географическое преобразование и высота. Генераторы карты и остановок исключают записи с `ref_v`. По наличию скриптов нельзя восстановить происхождение каждого численного параметра. Оснований заявлять чтение эталона в рабочей ноде нет. [Настройка географического преобразования](https://github.com/Alexaid1/tram-backup-odometry/blob/b2cfa3d94844cf3b8e1e129a026702bb7b9beeb2/tools/fit_geo.py#L1).

Полезные идеи: раздельные ограниченные коэффициенты тяги и тормоза, их адаптация только при надёжных колёсах, обновление общего масштаба пути по остановкам с учётом разброса ориентира. Наш фильтр сейчас адаптирует добавку ускорения, а остановки меняют только привязку положения. [Адаптация тяги и тормоза](https://github.com/Alexaid1/tram-backup-odometry/blob/b2cfa3d94844cf3b8e1e129a026702bb7b9beeb2/ros2_ws/src/tram_odometry/src/core/traction_model.cpp#L53).

### Vectra

Проверочная конфигурация калибруется по обучающей выборке. Конфигурация для жюри явно обозначена как калиброванная по обучающей и контрольной выборкам. Эти варианты нужно различать при переносе опубликованной оценки на поставляемый пакет. [Конфигурация для жюри](https://github.com/kitay-sudo/vectra-tram-odometry/blob/cbe17f1d88208a5086e6a4956c6de55270c04843/ros2_ws/src/tram_state_estimator/config/tram.yaml#L1).

В ROS-ноду также включён сдвиг скорости на 80 мс при текущей метке. Офлайн-оценка ядра этот сдвиг не применяет. [Публикация скорости](https://github.com/kitay-sudo/vectra-tram-odometry/blob/cbe17f1d88208a5086e6a4956c6de55270c04843/ros2_ws/src/tram_state_estimator/tram_state_estimator/tram_node.py#L681).

На 12 контрольных записях 30618 их средняя пространственная ошибка UKF — 1,91 м, колёсной базы с той же картой и остановками — 1,85 м. Собственный отчёт подтверждает пользу UKF для скорости, но не преимущество по этому показателю положения. [Отчёт Vectra](https://github.com/kitay-sudo/vectra-tram-odometry/blob/cbe17f1d88208a5086e6a4956c6de55270c04843/docs/EVAL.md#L304).

Дополнительные идеи: адаптация масштаба между остановками с откатом при несогласованных участках, оценка шума датчика по вторым разностям, несколько вариантов терминальной ветки и правило выбора. Правило ветки использует маршрутные закономерности и частоты из обучения, оно требует проверки на новых поездках. [Адаптация масштаба](https://github.com/kitay-sudo/vectra-tram-odometry/blob/cbe17f1d88208a5086e6a4956c6de55270c04843/ros2_ws/src/tram_state_estimator/tram_state_estimator/runner.py#L829). [Оценка шума](https://github.com/kitay-sudo/vectra-tram-odometry/blob/cbe17f1d88208a5086e6a4956c6de55270c04843/ros2_ws/src/tram_state_estimator/tram_state_estimator/estimator_core.py#L986).

### Ange1ika и AlexKochnov

Сравнение файлов выявило различия только в `reports/dataset/bags.csv`, `reports/dataset/topics.csv` и `results/position/per_bag.csv`. Исходники, карта, конфигурация, README и документация совпадают побайтно. Вывод касается содержимого, без предположений об авторстве.

В работе используется один восьмисостоянийный EKF. Двойной фильтр применяется при офлайн-оценке параметров. Масса — эффективный параметр модели, который также поглощает ошибки других параметров. GNSS используется для начальной позиции и курса, затем подписки закрываются.

Их отдельная полезная идея — оценка шага квантования колёсного датчика по окну прошлых приращений и коррекция масштаба только при достаточной уверенности. У нас масштабы фиксированы для каждой машины и тележки. [Квантование колёс](https://github.com/Ange1ika/tram_backup_odometry_ws/blob/425118d34d4619ec1ad33718e720df7907582925/src/tram_model_core/tram_model_core/quantization.py#L21).

Разделение 70/16 учитывает дубликаты, но не гарантирует разделение по датам записи. Генератор карты содержит запасной путь с доступом ко всем записям. У поставленной карты этот участок отмечен как построенный по обучающей записи `30618_0652866c`. Это риск повторного построения, не доказательство утечки в готовой карте. [Генератор карты](https://github.com/Ange1ika/tram_backup_odometry_ws/blob/425118d34d4619ec1ad33718e720df7907582925/tools/build_track_map.py#L310).

### artaila и b1ank37

У artaila README называет фильтр EKF, фактически создаётся `UnscentedKalmanFilter`. Нода задаёт пустую геометрию пути и высоту 0. Синхронизатор ждёт переднее колесо, заднее колесо и контроллер в окне 50 мс. При длительной потере любого потока новые выходы прекращаются. При возобновлении интервал ограничивается 0,25 с. [Нода artaila](https://github.com/artaila/odometry/blob/659f363e7bacb4c10417ef7e01f415f066a3c45e/tram_odometry_solution/src/tram_navigation/tram_navigation/telemetry_synchronizer_node.py#L145).

У b1ank37 состояние обновляется по передней тележке. Заднее показание хранится без контроля давности, таймер может повторять устаревшие состояние и метку. GNSS-координаты непосредственно заменяют позицию без проверки качества и плеча антенны. Курс обновляется по GNSS-скорости и остаётся постоянным при её отсутствии. [Нода b1ank37](https://github.com/b1ank37/mttex-tram-odometry-hackathon/blob/15616bf09efbddcbf2defab14311182eba36cc02/src/tram_reserve_odometry/tram_reserve_odometry/reserve_odometry_node.py#L119).
