# Точность и быстродействие

**Текущий кандидат: 3D RMSE 2,615 м по GNSS-прокси на 13 validation-записях при GNSS только в первые 1,5 с.** На более раннем коде `8164061` официальный открытый checker дал RMSE положения 1,562 м и скорости 0,052 м/с; это другой прогон и другой эталон.

Коррекция по остановкам отдельно уменьшила validation 3D RMSE **3,07993→2,64424 м** на 301 243 совпадающих метках; 8 записей улучшились, 3 ухудшились, 2 не изменились. [Методика и ограничения](../STOP_LANDMARKS_2026-09-27.md). Следующее правило выбора ветви изменило показатель **2,64424→2,61532 м** на тех же входах и метках. Оба результата относятся к GNSS-прокси и уже изученной validation, поэтому не подменяют скрытую проверку.

## Текущий кандидат: правило ветви поверх коррекции по остановкам

Полный C++ `Navigation` replay на 13 validation bag трамвая 30618: алгоритм получал GNSS только в первые **1,5 с** записи; дальнейшая GNSS использовалась для офлайн-оценки. Карта и параметры в A/B одинаковы. Базовая версия содержит коррекцию по остановкам, новая дополнительно выбирает альтернативную ветвь на конкретной развилке по состоянию колёс и команде контроллера. Эталон оценки — согласованная пара GNSS, не `/localization/kinematic_state` официального checker.

| Показатель | База | Текущий кандидат |
|---|---:|---:|
| Сопоставленных позиционных меток | 301 243 | 301 243 |
| Совокупный 3D RMSE | 2,64424 м | **2,61532 м** |
| Средний 3D RMSE по bag | 2,31709 м | **2,27658 м** |
| Средняя ошибка конечной позиции | 5,34843 м | **3,29193 м** |

Улучшилась одна запись `30618_a869780d`: 3D RMSE **2,25623→1,72963 м**, конечная ошибка **30,0611→3,3266 м**. Остальные 12 записей не изменились. В выходных CSV всех 13 записей временные метки, оценки скорости и накопленного пути A/B совпали точно. На двух train-записях ветви A правило выбрало A, на десяти train-записях B сохранило B. На 32 исторических записях 30618 переключений не было; достоверно размечены только четыре B. Validation уже использовалась при выборе метода и **не является слепой**. Отдельной независимой записи ветви A нет. [Подробная методика, результаты, ограничения и JSON](../BRANCH_BEHAVIOR_2026-09-27.md).

Архива открытого checker с записью `30618_88aea4d9` сейчас нет, поэтому официальный балл текущего кандидата не измерен. Ниже исторический официальный результат для `8164061`; новые поправки нельзя приписывать этому результату. Для текущего исходного дерева выполнены сборка ROS 2 Humble, **21/21 CTest** и **40/40 Python-тестов** в Ubuntu 22.04. [Сводка последней проверки](../../evaluation/results/final_candidate_20260927/summary.json).

На текущем исходном дереве также воспроизведена реальная validation-запись `30618_a869780d` в ROS с GNSS-fix только первые 1,5 с; GNSS-скорость и эталон не подавались. За первые 80 с при 1× опубликовано 2088 позиций со средней частотой **26,10 Гц** по меткам сообщений; внутренняя задержка от входного callback до публикации позиции p95 **0,272 мс**, максимум **1,395 мс**. Полный bag длительностью 1083,8 с прошёл при 8×: 27 886 позиций, 27 890 скоростей, 25,74/25,73 Гц по меткам, все конечные значения, выбранная ветвь A, пиковая RSS ноды **24,99 MiB**, средний CPU **0,086 ядра** во время ускоренного прогона. На всех 27 886 метках положения ROS и C++ офлайн replay совпали с допуском 1 мс; после первых 5 с максимальное расхождение координат **2,2 мм**, момент выбора A совпал. Это проверка ROS-интеграции и внутренних ресурсов, **не** официальный checker и не измерение полной задержки доставки сообщения. [ROS-отчёт](../../evaluation/results/final_candidate_20260927/ros_runtime.json) · [Сверка с офлайн-ядром](../../evaluation/results/final_candidate_20260927/ros_offline_comparison.json).

На этом ROS-прогоне коррекция по маркеру остановки единожды сдвинула позицию на **1,536 м** при нулевой скорости. Проверенное в черновике каузальное сглаживание на 5 с снизило наибольший шаг у этой остановки до 0,023 м, но ухудшило совокупный validation RMSE **2,61533→2,61964 м** на тех же 301 243 метках; в поставляемую версию оно не вошло. [Детальные результаты](../../evaluation/results/final_candidate_20260927/rejected_stop_smoothing.json). Этот остаточный скачок отмечен в [ограничениях](LIMITATIONS.md).

## Проверка по GNSS исходного датасета

97 уникальных записей разделены по целым сессиям «трамвай + дата»: обучающая выборка — 42, валидационная — 13, историческая контрольная — 42. Пересечение дубликатов между выборками исключено. Карта и калибровки построены по обучающей выборке.

Оценка скорости по GNSS для сравнения использует модуль пространственного вектора скорости основной (`master`) и второй (`rover`) антенн и ближайшие показания с допуском 50 мс: при согласии двух скоростей до 0,3 м/с — их среднее, при доступности одного приёмника — его значение. Несогласованные пары исключаются. GNSS-оценка скорости используется для проверки точности.

| Набор | Записей с GNSS-оценкой / всего | Сопоставлений | RMSE скорости |
|---|---:|---:|---:|
| Обучающая выборка, обе машины | 42 / 42 | 939478 | 0,057982 м/с |
| Валидационная выборка, 30618 | 13 / 13 | 286515 | 0,033146 м/с |
| Историческая контрольная выборка, обе машины | 23 / 42 | 431768 | 0,118075 м/с |

Оценка скорости выполнена на 23 из 42 контрольных записей с пригодными GNSS-измерениями.

В 284 одинаковых валидационных окнах удалены сообщения обоих колёс на 5,12 с. Сообщения контроллера продолжают поступать. Эталон пути — интеграл очищенной GNSS-скорости. Ошибка измеряется от начала каждого обрыва:

| Горизонт обрыва | RMSE скорости | RMSE пути |
|---|---:|---:|
| 1 с | 0,134484 м/с | 0,076536 м |
| 3 с | 0,379171 м/с | 0,577486 м |
| 5 с | 0,533883 м/с | 1,466822 м |

Проверка включает сравнение с GNSS и моделирование потери обоих колёсных датчиков.

Дополнительно проверен случай, когда обе тележки продолжают публиковать
одинаковые постоянные значения после начала сильного торможения. Узкий
детектор уменьшил в синтетическом сценарии 30618 RMSE скорости
0,545→0,047 м/с и пути 8,25→0,64 м; на 97 реальных train/validation/исторических
holdout bag прежняя и экспериментальная версии выдали одинаковые результаты.
Этот тест подтверждает реакцию на конкретный отказ и не заменяет официальный
скрытый прогон. [Условия срабатывания и ограничения](../PAIR_FREEZE_BRAKE_2026-09-27.md).

## Исторический замер быстродействия официального прогона `8164061`

Ubuntu 22.04 / ROS 2 Humble, arm64, Docker с лимитом 2 CPU и 512 MiB. Измерялся только процесс `odometry_node`.

| Показатель | Результат |
|---|---:|
| Средняя частота `/result/position` по временным меткам сообщений | 21,75 Гц |
| Задержка вход→положение, p50 / p95 / max | 1,774 / 4,385 / 27,316 мс |
| Задержка вход→скорость, p50 / p95 / max | 1,166 / 3,937 / 16,495 мс |
| CPU, среднее / p95 | 2,91% / 5,49% одного ядра |
| Пиковая память | 24,64 MiB |

Задержка измерена внешним наблюдателем по монотонным часам между приёмом входного сообщения контроллера или датчика передней/задней тележки и результата с той же меткой. Она включает DDS и планирование наблюдателя. Внутренняя задержка обработчика сообщения публикуется отдельно в диагностике. CPU измерен по `/proc`, 100% означает одно ядро. Память — `VmHWM`. Замеры выполнены при фоновой нагрузке на хосте.
