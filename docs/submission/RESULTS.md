## Открытый контрольный прогон

Bag организаторов: `30618_88aea4d9`. Эталон — `/localization/kinematic_state`, выход комплексированной системы. Для положения сравниваются XYZ точки `base_link`, для скорости — `twist.twist.linear.x` эталона.

Официальный checker использует ROS `ApproximateTimeSynchronizer`: допуск 50 мс, очередь 100. `RMSE = sqrt(mean(error²))`; для 3D берётся евклидова норма вектора ошибки. Полный прогон завершён при 1× за 1316,26 с, записаны все 65579 сообщений эталона; checker сформировал 28538 пар для каждого результата.

## Проверка по GNSS исходного датасета

97 уникальных bag разделены по целым сессиям «трамвай + дата»: train 42, validation 13, исторический holdout 42. Дубликаты не пересекают наборы. Карта и калибровки построены по train.

GNSS-прокси скорости использует 3D-модуль вектора скорости master/rover и ближайшие показания с допуском 50 мс: при согласии двух скоростей до 0,3 м/с — их среднее, при доступности одного приёмника — его значение. Несогласованные пары исключаются. Прокси не поступает в рабочий фильтр.

| Набор | Bag с прокси / всего | Сопоставлений | RMSE скорости |
|---|---:|---:|---:|
| Train, обе машины | 42 / 42 | 939478 | 0,057982 м/с |
| Validation, 30618 | 13 / 13 | 286515 | 0,033146 м/с |
| Исторический holdout, обе машины | 23 / 42 | 431768 | 0,118075 м/с |

В 284 одинаковых validation-окнах удалены сообщения обоих колёс на 5,12 с; контроллер продолжает поступать. Эталон пути — интеграл очищенной GNSS-скорости. Ошибка измеряется от начала каждого обрыва:

| Горизонт обрыва | RMSE скорости | RMSE пути |
|---|---:|---:|
| 1 с | 0,134484 м/с | 0,076536 м |
| 3 с | 0,379171 м/с | 0,577486 м |
| 5 с | 0,533883 м/с | 1,466822 м |

Это диагностика по GNSS и искусственные пропуски, а не score скрытого теста или доказательство работы при любом скольжении. 19 holdout-bag без пригодного прокси не получают нулевую ошибку. Исторические наборы уже анализировались при разработке.

## Быстродействие

Ubuntu 22.04 / ROS 2 Humble, arm64, Docker с лимитом 2 CPU и 512 MiB. Измерялся только процесс `odometry_node`.

| Показатель | Результат |
|---|---:|
| Средняя частота `/result/position` по header-меткам | 21,75 Гц |
| Задержка вход→положение, p50 / p95 / max | 1,774 / 4,385 / 27,316 мс |
| Задержка вход→скорость, p50 / p95 / max | 1,166 / 3,937 / 16,495 мс |
| CPU, среднее / p95 | 2,91% / 5,49% одного ядра |
| Пиковая память | 24,64 MiB |

Задержка измерена внешним наблюдателем по монотонным часам между приёмом входа C/F/R и результата с той же меткой; включает DDS и планирование наблюдателя. Внутренняя задержка callback публикуется отдельно в диагностике. CPU измерен по `/proc`, 100% означает одно ядро; память — `VmHWM`. На хосте выполнялись и другие проверки, это не изолированный аппаратный benchmark.
