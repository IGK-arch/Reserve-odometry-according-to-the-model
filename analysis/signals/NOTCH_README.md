# Что можно узнать из положения контроллера

Это **разведочный офлайн-анализ**, а не готовая калибровка тягового привода. По `dataset/README.md` позиции `+1…+15` тяговые, `−1…−15` тормозные. Наблюдаемая скорость колёс в записи требует деления на 3,6, несмотря на заявленные м/с.

## Метод

- Оставлены 76 уникальных bag с обеими GNSS-скоростями (58 для 30618, 18 для 30639); точные дубликаты `.db3` исключены.
- Временная сетка 0,1 с. Скорость GNSS master интерполирована, ускорение получено сглаживанием Савицкого — Голея по 11 точкам и производной. **Фильтр центрированный и использует будущие точки; применять его в онлайн-ноде нельзя.**
- Исключены точки с расхождением двух GNSS >0,3 м/с, тележек >0,25 м/с или среднего колёс и GNSS >0,5 м/с. Сравнение разбито по скорости и длительности удержания позиции.
- В таблице `notch_speed_dwell_summary.csv` есть суммы ускорения, квадраты, медиана и число точек по bag/позиции/скорости/выдержке. График `notch_response_speed_dwell.png` показывает лишь позиции с ≥100 точками в каждом диапазоне скорости при выдержке ≥1 с. `minus15_episodes.csv` содержит отдельные эпизоды позиции −15.

## Почему среднее для −15 кажется слабым

| Трамвай | Точки −15 после фильтрации | Доля точек −15 при скорости <1 м/с | Эпизоды −15 с согласованными GNSS | Доля эпизодов с начальной скоростью <1 м/с |
| --- | ---: | ---: | ---: | ---: |
| 30618 | 4 307 | 82,1% | 564 | 89,7% |
| 30639 | 1 250 | 79,2% | 127 | 81,9% |

При остановке отрицательное ускорение ограничено нулевой скоростью; поэтому простое среднее `a | position=−15` смешивает сильное торможение с длительным удержанием почти стоящего трамвая. После выдержки позиции ≥1 с и при **3–8 м/с** среднее для −15 составляет **−0,836 м/с² по 161 точке** у 30618. Для 30639 в этой области всего **11 точек**, чего недостаточно для надёжной калибровки. Сравнение −15 с −14 без контроля скорости и фазы торможения вводит в заблуждение: при выдержке ≥1 с у −14 всего три точки у 30618 и ни одной у 30639.

Есть и более важная неоднозначность. В `30618_27e994fc` примерно **1815–1821,6 с** от первого отсчёта GNSS master скорость растёт с ~0,9 до ~2,0 м/с, пока позиция непрерывно передаётся как −15 с интервалом около 0,05 с. В `30639_c31df386` примерно **1332,4–1334,2 с** скорость растёт с ~0,9 до ~2,0 м/с при том же тормозном значении. GNSS master, GNSS rover и обе тележки при этом согласованы. Значит, эти эпизоды **не объясняются только ошибкой GNSS, проскальзыванием одной тележки или отсутствием сообщений контроллера**. Набор доступных каналов не позволяет установить причину: возможно, команда не равна фактически приложенному моменту, есть задержка/иная логика привода либо неучтённое воздействие. Нельзя считать −15 известным фиксированным тормозным моментом на каждом такте.

## Следствие для модели

Калибровать `a_model(position, speed)` следует раздельно по трамваю, в диапазонах скорости, на движущихся участках и после проверки времени с момента смены позиции. Начать с робастной регрессии по согласованным GNSS/тележкам, но **не заставлять данные автоматически задавать монотонную карту для −15**. Редкие или противоречивые режимы нужно помечать как неидентифицированные; в онлайн-оценке задавать им широкую неопределённость и опираться на согласованные колёса. При сомнительных колёсах модель применима лишь как кратковременный прогноз с растущей ковариацией. Проверять карту по отложенным целым bag, а не случайно перемешанным точкам.

Воспроизведение: `py -3.12 analysis/signals/notch_deepdive.py` и `py -3.12 analysis/signals/inspect_notch15.py` из корня проекта. Нужны `numpy`, `pandas`, `scipy`, `matplotlib`. Скрипты только читают bag и пишут полученные файлы в эту папку.
